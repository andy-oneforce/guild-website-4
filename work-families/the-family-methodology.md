# The family methodology

The methodology starts from one statement of how ASI OS should behave.

> When you state what you want to do, the system takes the active role. It guides you step by step: it collects scope, goal, other objectives and context, decides the route, selects the phase, asks questions, and writes clear documents for you to review and approve. Once approved, it carries the work forward with limited involvement from you, in iterations.

The five stages that follow from it are on [How work is organised](../start-here/how-work-is-organised.md). Every idea from the earlier approach was tested against one question: does it help this flow?

## What was kept

| Idea | Why it stays |
| --- | --- |
| Name documents for the question they answer | Still the best naming rule, and the system needs it to know which document to write at each stage |
| Keep the name "recommendation" | The name is standard and widely embedded |
| The answer comes first | Approval at stage 3 depends on seeing the proposal immediately |
| Tier decides how many documents exist | A small request should not get five documents |
| New kinds: assessment, verification, retrospective, inventory, mapping | Each answers a question the flow asks |
| Closed work is not renamed | Citations keep working |

## What was dropped

| Idea | Why it goes |
| --- | --- |
| The nine-question spine as the shared process | It describes a finished piece of analysis, not a way to run work. It put assessment and decision before any building, which is wrong when the first result should be a prototype or draft |
| The rating table (heavy, usual, rare) | Judgement-based and not tied to the flow; replaced by the route table |
| The north star as a section of an assessment | A north star for a piece of work is now a field in its scope |

There is no measurement yet of whether guided work produces better results. The evidence behind the earlier approach describes what past documents look like; the new north star describes how future work should run. A pilot on live work is how it will be tested.
