# ASI OS work methodology

When you tell ASI OS what you want to do, the system takes the active role. It asks the questions, picks a route, drafts a first result for you to approve, builds it with little involvement from you, and then improves it in rounds.

This site explains the rules behind that flow: how work is organised, how an idea finds its home, which documents each kind of work produces, and how results reach the knowledge base.

New here? Start with [What this site covers](start-here/what-this-site-covers.md), then read [How work is organised](start-here/how-work-is-organised.md).
